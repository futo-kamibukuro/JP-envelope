# SuguCheck（リスト診断・クレンジングツール）v0.1

DM発送用リスト（CSV／TSV）を発送前に自動診断し、問題箇所を可視化する軽量Webツールです。
「仕様書 v0.1 ドラフト」の MVP（13章）を実装しています。

- **確実に安全な修正だけを自動化**し、すべて修正ログに残します（元の値を保持）
- 判断が必要なものは**事象別のエラーリスト**にしてクライアントに戻します
- 重複はレコードを削除せず、**除外候補フラグ**を付けます。要確認候補はどの設定でも自動で除外しません
- すべての指摘に**ルールID**を付けます。生成AIは使わず、ルールベースで完結します

## 個人情報の扱い（ブラウザ内処理）

読み込んだファイルは**利用者のブラウザ内（Web Worker）だけで処理**します。サーバーへのアップロード、外部APIや生成AIへの送信は一切行いません（`index.html` の Content-Security-Policy で外部への通信も禁止しています）。
データはブラウザに保存せず、「データを消去」またはタブを閉じるとメモリから消えます。

このため、仕様書 9.1 のうち次の項目はこの構成で満たされます：外部の生成AIに送信しない／アップロードファイルの自動削除（サーバーに保持しない）／テナント間のデータ分離（データが利用者の端末から出ない）。
TLS は配信するWebサーバー側（HTTPS）で設定してください。実行ログのサーバー保存・複数テナント運用は v1.0（SuguPOS連携）での対応を想定しています。

## 使い方

```bash
npm install
npm run dev       # 開発サーバー（http://localhost:5173）
npm test          # 受入テスト（仕様書14章 T1〜T3・T6・T7 ほか）
npm run build     # dist/ に静的ファイルを出力
```

`dist/` を任意の静的ホスティング（HTTPS）に置けば動作します。画面の「サンプルデータで試す」で、講義の事例（名寄せ6件・Excel破損・外字など）を含むサンプルを診断できます。

### 画面の流れ

1. **アップロード**：CSV／TSV（.csv .tsv .txt、上限200MB）。.xlsx は v0.2 予定、.xlsm は拒否
2. **読込結果・列マッピング**：文字コード（UTF-8／Shift_JIS(CP932)／EUC-JP を自動判定、手動変更可）、区切り文字、ヘッダ有無。全列を文字列として先頭30行をプレビュー。ヘッダ名から標準種別を推定（データ値は使わない）
3. **ルール設定**：項目定義（必須・最大文字数・文字種・固定桁・正規表現・許容値）、重複キー（P1〜P6 の多段適用）、許容度（厳格／標準／緩め）、代表レコード選定、正規化オプション、自動修正のON/OFF。実行条件JSONの読込
4. **診断結果・ダウンロード**：サマリー → ルール別 → 明細（フィルタ・行ジャンプ・行詳細）。明細から修正案を選んで「適用して再診断」。重複タブで要確認候補・重複グループを確認

### 出力

| ファイル | 内容 |
|---|---|
| 診断レポート（HTML） | 件数・ルール別件数・発送可能見込み件数・実行条件。印刷でPDF化 |
| クレンジング済みデータ（xlsx） | **全セル文字列型**（書式も「@」）。データ／実行条件・サマリー／修正ログの3シート |
| クレンジング済みデータ（CSV） | UTF-8 BOM付き／CP932 を選択。全項目クォート、CSVインジェクション対策あり |
| エラーリスト（xlsx） | ①住所・郵便番号 ②文字 ③重複候補 ④形式・破損疑い ＋ 除外候補（参考）。回答期限・担当部署欄、判断欄（採用／修正値／除外／そのまま のプルダウン） |
| 修正ログ（CSV） | 行ID・項目・修正前・修正後・ルールID・区分 |
| 実行条件（JSON） | 同じ条件で再実行するための設定一式（ファイルのSHA-256付き） |
| 一式（zip） | 上記すべて＋注意文（「CSVをExcelで直接開かない」等） |

追加列：行ID、チェック結果コード、重複グループID、除外候補フラグ、除外理由、要確認候補ID、同一世帯ID、修正有無

## 実装したチェック

MVP の対象（F-01, F-02, F-03, F-06／E-01〜E-05／C-01, C-02, C-04, C-05／A-01, A-07, A-08, A-09／D-01〜D-04）に加え、実装コストが小さいものを前倒ししています：
F-07（ヘッダ重複・未定義列）、E-06（数字の全半角）、C-03（機種依存文字の置換案）、C-06（不可視文字）、V-01／V-02（項目定義の正規表現・許容値）、重複キー P4〜P6、D-05（代表選定）。

ルール一覧（ID・重大度・自動修正区分・出典）は `src/core/rules.ts` にあります。

### 判定の補足

- **文字の水準（C-01）**：JIS X 0208（第1・第2水準）の文字表はブラウザ標準の文字コード変換表から生成しています。CP932 の NEC特殊文字・IBM拡張文字（髙・﨑 など）は「範囲外（CP932拡張）」として区別します。JIS X 0213 の表は持っていないため、CP932 で表現できない漢字は「第3・第4水準の**可能性**」と表示します
- **重複**：キー（P1〜P6）が一致しても、氏名が異なる場合は常に要確認候補（D-04）にします。標準・厳格では住所や郵便番号の食い違いも要確認、緩めではキー一致を優先します。同一住所の氏名1字違いは要確認候補、まったく別の氏名は「同一世帯」として扱います
- **日付化（E-04）**：住所系の列で yyyy/m/d、m月d日、d-mmm、番地欄のシリアル値（20000〜60000）を検出します。破損疑いの値は書き換えません
- **CSVインジェクション**：= @ で始まる値、および + - で始まり数字・記号以外を含む値の先頭に ' を付けます。「+81-3-…」のような電話番号はそのまま出力します（仕様書 9.1 の「要検討」への暫定対応）

## 構成

```
src/core/      診断エンジン（UIに依存しない純粋なTypeScript）
  charset.ts     文字コード判定・CP932エンコード・JIS水準判定
  csv.ts         CSV/TSVパーサー（全列文字列）・CSV出力
  layout.ts      標準種別・プリセット・ヘッダ推定
  checks.ts      セル単位のチェックと修正
  dedupe.ts      名寄せ（D-01〜D-05）
  engine.ts      診断の実行・サマリー
  outputs.ts     レポート・エラーリスト・修正ログ・zip
  xlsx.ts        xlsx書き出し（全セル文字列）
src/worker.ts  Web Worker（診断処理）
src/ui/        画面（Preact）
test/          受入テスト（vitest）
```

性能の目安（Node.js での計測）：10万行×12列で読込0.5秒、診断約4秒、一式zip作成約19秒。
